# Repository audit — 2026-10-03

This review started from commit `be558d1` (`v0.6.5-3-gbe558d1`) and includes
the accompanying code, regression tests and documentation changes. It covers
correctness, performance, security, shared implementation, usability, Go
conventions and test coverage. No release or publication was performed.

## Scope and method

The review covered CLI parsing and validation, source expansion, globbing,
planning and overwrite decisions, local file identity and attributes, worker
ordering, Azure authentication, listing and transfer routes, checksums,
compression, resume records, filtering and deletion, retries, cancellation,
terminal output, metadata, URI handling, dependencies and release workflows.

The baseline passed `make check`. Local behavior changes were checked against
the installed **GNU coreutils 9.4**, the repository's reference version. The
new [comparison script](../scripts/cp-compat.py) exercises 420 combinations of
operand shapes and options in isolated temporary directories. It compares exit
status, contents, permissions, preserved modification times, symlink targets
and hard-link relationships. New Go tests cover individual failures, including
attributes and diagnostics the script does not compare.

Azure changes were exercised through HTTP fixtures and the Azurite end-to-end
suite. Fixtures cover paging, authentication generations, checksums, conditional
requests and server-side APIs that Azurite does not implement. All checks ran
on Linux/amd64 with Go 1.27.1.

## Corrected findings

| Area | Failure and correction | Evidence |
| --- | --- | --- |
| Local concurrency | Different destination names could write the same inode concurrently. A destination could also truncate a file while an earlier task was reading an alias, or a later source could be read before an earlier writer completed. Scanner-owned dependencies now order these operations and refresh source attributes after an earlier write. Independent copies remain parallel. | [Regression tests](../internal/engine/regression_test.go), [dependency scheduling](../internal/engine/dependencies.go) |
| Destination link graph | `--preserve=links` could retain hard links between destination names whose sources were unrelated, leaving both copies with one file's contents. Such destinations are separated without allowing a same-file copy. | [Regression tests](../internal/engine/regression_test.go) |
| Symlinks and `-u` | Update decisions compared a destination symlink's own timestamp instead of the target being written. Equal timestamps could also hide a same-file error. Both now follow GNU's ordering and exceptions. | [Regression tests](../internal/engine/regression_test.go), 420-case comparison |
| Link creation | `-l` linked a source symlink itself instead of its target, including under recursion; copied symlinks could incorrectly refuse an existing destination. Dereference, interactive replacement, no-dereference and error wording now follow the reference. | [Regression tests](../internal/engine/regression_test.go), 420-case comparison |
| Dangling destinations | The directory index skipped dangling symlinks under `-n` without GNU's validation. Symlinks now take the stat route. Under `POSIXLY_CORRECT`, a missing target is treated as missing even with no-clobber, update or interactive flags. | [Index tests](../internal/engine/destindex_test.go), [regression tests](../internal/engine/regression_test.go) |
| Attributes | Preserved atime could be read after copying had changed it. Attribute application could operate on a destination symlink instead of the file copied through it. Source snapshots now retain the original attributes; link-following and no-follow operations are explicit. | [Attribute tests](../internal/engine/attribute_copy_test.go) |
| Creation modes and parents | `--no-preserve=mode` still used source permissions, and `--parents` omitted intermediate source directory attributes. Creation modes and parent preparation now match GNU behavior. A recursive source can create a missing `DEST/`. | [Attribute tests](../internal/engine/attribute_copy_test.go), [directory tests](../internal/engine/directories_test.go) |
| GNU option values | Enum prefixes, empty values, preserve lists, backup suffixes, duplicate target-directory flags and help/version ordering differed from GNU. Validation now uses shared GNU-style choice handling and rejects incompatible reflink/sparse settings before copying. | [CLI tests](../internal/cli/cpvalues_test.go) |
| Numeric limits | Extreme worker, part-concurrency and retry values could overflow SDK or queue arithmetic. Limits are validated before constructing a run. Minimum signed sizes and durations no longer overflow display formatting. | [CLI tests](../internal/cli/cpvalues_test.go), [humanize tests](../internal/humanize/humanize_test.go) |
| Backup numbers | Numbered backups could overflow a machine integer and select an unsafe or incorrect name. Decimal suffixes now use arbitrary-precision arithmetic. | [Regression tests](../internal/engine/regression_test.go), [backup helpers](../internal/engine/backup.go) |
| Pruning | An excluded child did not reliably protect its containing directories, and destination walk failures could be missed. Retained ancestors are protected, queued directory removals are rechecked, overlapping roots record retention correctly, and incomplete listings fail. Dry runs use the same decisions. | [Regression tests](../internal/engine/regression_test.go), [pruner](../internal/engine/prune.go) |
| Resume ownership | Any `.azcp-part` name could be treated as unfinished state, bypass no-clobber, or be truncated/deleted. Only regular files with the full resume magic are recognized. Symlinks and unrelated files are refused; record rewrites replace the sidecar without modifying hard-link aliases. | [Resume tests](../internal/store/azure/resume_test.go), [index tests](../internal/engine/destindex_test.go), Azurite |
| Resume name collisions | A downloaded blob could occupy another download's sidecar name, including within one source tree. The planner reserves record names and reports collisions before concurrent writes can corrupt them. | [Remote tests](../internal/engine/remote_test.go), Azurite |
| Decompression identity | Replacing the destination with a temporary file broke existing hard links and destination symlinks. Ordinary decompression now streams into the opened destination. Resumed decompression invalidates saved compressed ranges before rewriting the existing inode. | [Remote tests](../internal/engine/remote_test.go), Azurite |
| Listing completeness | Split discovery could stop at its inventory cap and partition only the names seen so far, omitting later blobs. Incomplete inventories now fall back to the original pager. Split prefixes also end at valid UTF-8 boundaries. | [Split-listing tests](../internal/store/azure/split_test.go) |
| Listing replay and cancellation | Authentication recovery could replay pages whose callbacks had already queued copies. A walk now restarts only before emitting any node; look-ahead workers are joined on cancellation. | [Walk tests](../internal/store/azure/walk_test.go) |
| Exact blob keys | URL joins and trailing-slash handling collapsed significant key characters. Remote copies preserve repeated slashes and encoded final slashes; local downloads reject unsafe tree mappings. Directory pruning deletes the exact marker, keeping any unsuffixed blob separate. | [URI tests](../internal/uri/uri_test.go), [naming tests](../internal/store/azure/naming_test.go), Azurite |
| Short writes | Ordered downloads and decompression could accept a nil-error short write as success, losing data or miscounting progress. They now return `io.ErrShortWrite` and count bytes actually written. | [Stream tests](../internal/store/azure/stream_test.go), [pipe implementation](../internal/engine/pipe.go) |
| Copy checksums | Some blob-to-blob routes lost the source MD5. A streamed fallback could commit bytes before detecting a mismatch. Every route carries the digest, and streaming verification happens before upload completion. | [Copy tests](../internal/store/azure/copy_headers_test.go) |
| Concurrent blob replacement | Checksum/header and attribute updates could change a newer blob. Conditional requests now bind updates to the observed version; attributes-only creation cannot truncate a concurrently created blob. Async polling checks its copy ID, and a failed version condition stops route fallback. | [Copy tests](../internal/store/azure/copy_headers_test.go) |
| Authentication scope | An environment connection string could redirect a different account's URL to its own endpoint. Static secrets are scoped by account, cached clients include credential generation, and a started browser sign-in cannot trigger a second device prompt after failure. | [Authentication tests](../internal/store/azure/auth_static_test.go) |
| Brace expansion | Expansion silently returned only a prefix after reaching its limit, and integer sequences could wrap. Exceeding 8,192 results now errors; range arithmetic and character-sequence recognition follow the tested Bash behavior. | [Brace tests](../internal/glob/braces_limits_test.go), [Bash differential tests](../internal/glob/bash_compat_test.go) |
| Globstar performance | Repeated `**` components recursively explored exponentially many partitions for a nonmatch. Iterative matching keeps the latest globstar as the backtracking point. | [Glob tests](../internal/glob/glob_test.go), benchmark below |
| Compression streams | Raw deflate detection consumed bytes before falling back, corrupting non-seekable input. Header inspection now leaves the bytes available to the selected decoder. Zstd decoding uses one worker per stream instead of multiplying per-file concurrency. | [Codec tests](../internal/codec/codec_test.go) |
| Diagnostics and secrets | Filenames containing controls could inject terminal commands into ordinary diagnostics. Names now use visible shell escapes; prompts pass through redaction, and percent-encoded SAS signature keys are recognized. | [Regression tests](../internal/engine/regression_test.go), [logging tests](../internal/logx/logx_test.go) |
| POSIX metadata | Oversized owner IDs could truncate when passed to the OS, and non-ASCII/control-containing symlink targets could not be transported reliably as HTTP metadata. Bounds are validated and those targets use a base64 metadata field, retaining the ASCII representation for ordinary links. | [Metadata tests](../internal/store/posixmeta_test.go), Azurite |
| Publishing workflow | Workflow inputs and multiline output were interpolated directly into shell programs. Structured environment variables and version validation now keep those values out of shell syntax. | [Package workflow](../.github/workflows/packages.yml), shell review |

Azure metadata values are constrained to ASCII; the new link representation
follows that documented requirement. See Microsoft's
[blob naming and metadata rules](https://learn.microsoft.com/en-us/rest/api/storageservices/naming-and-referencing-containers--blobs--and-metadata).

## Performance and implementation

The existing request-count tests still pass: ordinary no-clobber reruns use a
directory index, and the listing fast paths retain their request budgets.
Only symlinks and candidate resume records require additional validation.
Completed local-reader dependencies are swept every 1,024 registrations;
live entries are bounded by queued and active tasks. No goroutine is added per
dependency, and the scanner waits only where file identities conflict.

The globstar microbenchmark uses six `**/a/` pairs followed by a missing
component against an 18-component path. Identical benchmark code was run against
the baseline and modified matcher, three times for 300 ms each, on an AMD
Ryzen 7 8840HS with Go 1.27.1 (`GOMAXPROCS=16`). Medians:

| Measurement | Baseline | Modified |
| --- | ---: | ---: |
| Time per nonmatch | 289,581 ns | 438.4 ns |
| Allocated bytes | 640 | 640 |
| Allocations | 2 | 2 |

This is roughly a 660-fold improvement on this adversarial matching workload.
It is not a measurement of transfer throughput. Reproduce the current side:

```sh
go test ./internal/glob -run '^$' -bench '^BenchmarkGlobstarNoMatch$' -benchmem -benchtime=300ms -count=3
```

Backup naming, diagnostic quoting, GNU value parsing and local dependencies
have separate focused files. Existing concrete transfer routes, the bounded
worker helper and terminal ownership model are retained. No runtime dependency
was added or upgraded.

## Limits and compatibility notes

- Native Windows and macOS tests were unavailable in this Linux workspace.
  Cross-compilation checks build correctness, not filesystem or keychain
  behavior. The changed platform attribute helpers still need native testing;
  Windows is covered by the existing CI matrix, macOS is not.
- No real Azure account, interactive browser/device authentication, platform
  secret store or cloud throughput was exercised. Fixtures and Azurite cannot
  establish parity with every service configuration.
- An empty or very early torn legacy sidecar cannot be distinguished from an
  unrelated user file. It is now refused rather than overwritten or trusted.
  Recognized stale/torn records restart safely. Resume-name collisions require
  resolving the names or copying without resume.
- Older binaries cannot restore links stored in `azcp_symlink_base64`.
  Ordinary ASCII link metadata remains compatible.
- Existing measured README transfer numbers were not remeasured against live
  Azure, and no new transfer-throughput claim is made here.
- Passing these checks is evidence for the covered cases, not a guarantee that
  every possible filesystem, concurrent external modification or option
  combination has been verified.
