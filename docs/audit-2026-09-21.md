# Service audit — 2026-09-21

This audit reviewed `azcp` from baseline commit `0233fba` (v0.6.0), concentrating
on correctness, performance, usability, shared implementation, Go conventions,
tests, and documentation. The fixes accompany this report; it does not
describe a tagged release.

## Scope and approach

The review covered command-line parsing, source expansion and planning,
overwrite and backup rules, directory and link handling, local copy paths,
Azure uploads/downloads/server-side copies, resume records, metadata,
compression, retries, cancellation, progress, logging, and the benchmark path.
Authentication, walking, filtering, deletion, throttling, and supporting
packages were also inspected and included in the existing test runs.

Findings were checked with focused regression tests and, for changed local
copy semantics, comparisons with the installed GNU coreutils `cp` 9.7. The
repository's compatibility reference remains GNU `cp` 9.4; that version was
not installed. Azure behavior was checked with HTTP fixtures and Azurite.

## Fixed findings

| Area | Problem and corrected behavior | Regression coverage |
| --- | --- | --- |
| File lists | Without an explicit destination, `--files-from` could consume its last source as the destination and overwrite input. Parsing now requires a command-line destination or `-t`. | [CLI file-list tests](../internal/cli/filesfrom_test.go) |
| Transformed names | Two files within one recursive source could map to the same compressed or decompressed destination. Collision tracking now applies to these single-source trees, including no-clobber, numbered-backup, and dry-run behavior. | [Compression tests](../internal/engine/compress_test.go) |
| Directory permissions | Recursive copies created directories with a fixed `0755`, potentially exposing private content. New local directories use the source permissions and umask; temporary owner access is restored after copying, including failure paths. Existing directories retain their permissions unless preservation is requested. | [Directory tests](../internal/engine/directories_test.go) |
| Destination parents | Recursive copies silently created missing destination parents. They now fail consistently with GNU `cp`. | [Directory tests](../internal/engine/directories_test.go) |
| Dangling symlinks | Ordinary copies could follow a dangling destination symlink and create its target. They now refuse by default, with the GNU `cp` exceptions for `POSIXLY_CORRECT` and operations that replace the link. The guard also applies to downloads. | [Safety tests](../internal/engine/safety_test.go) |
| Literal names | An existing filename containing braces could be expanded into unrelated source names. Automatic expansion now honors an existing literal local path; explicitly requested expansion still works. | [Safety tests](../internal/engine/safety_test.go) |
| Interactive input | A final affirmative answer without a newline was discarded. It is now accepted; subsequent unanswered prompts do not overwrite files. | [Overwrite tests](../internal/engine/overwrite_test.go) |
| Attributes-only copies | Blob-to-blob `--attributes-only` transferred content. It now uses the metadata/property path, preserving existing data. Its storage operation also enforces no-clobber for existing blobs. | [Remote engine tests](../internal/engine/remote_test.go), [Azure property tests](../internal/store/azure/copy_headers_test.go) |
| Asynchronous copy headers | Azure's asynchronous copy fallback ignored content-header overrides. Changed headers are now applied after completion, guarded by the destination ETag and retaining other source headers and MD5. Unchanged headers cause no extra request. | [Azure property tests](../internal/store/azure/copy_headers_test.go), [Azurite checks](../scripts/e2e.sh) |
| Incomplete downloads | The planner admitted recorded incomplete downloads with `-n`, but without `--resume` the worker refused to open them. They now restart from scratch and clear the record after success. | [Remote engine tests](../internal/engine/remote_test.go), [Azurite checks](../scripts/e2e.sh) |
| Recorded symlink attributes | Restored remote symlinks lost their requested attributes. Restoration now handles the link itself, skips symlink chmod, and preserves timestamps without modifying the target. Windows uses a reparse-point handle; unsupported platforms refuse unsafe timestamp operations. | [Attribute tests](../internal/engine/attrs_test.go), [Azurite checks](../scripts/e2e.sh) |
| macOS reflink safety | The clone path unlinked an open destination before attempting `clonefile`. Failure could leave the fallback writing to an unlinked inode; success broke destination hard links. macOS now uses ordinary copies for `--reflink=auto` and rejects `--reflink=always`. | [Local copy tests](../internal/store/local/copy_test.go); native macOS execution remains outstanding |
| Cancellation | A pre-cancelled local copy could truncate its destination. It now checks cancellation before opening it. Azure asynchronous copies also attempt an abort when cancellation occurs during a polling request. | [Local copy tests](../internal/store/local/copy_test.go), existing Azure cancellation tests |
| Durations and retries | Negative, non-finite, or oversized durations could be accepted, and extreme exponential backoff or `Retry-After` values could overflow. Input validation and saturating retry arithmetic prevent these cases. | [Duration tests](../internal/cli/duration_test.go), [Retry overflow tests](../internal/retryx/overflow_test.go) |
| JSON failures | Fatal planning errors bypassed the JSON summary. Runs that reach planning now emit a JSON error and final summary with the failure and a nonzero exit status. Argument/configuration validation can still fail before the JSON run starts. | [Output tests](../cmd/azcp/output_test.go) |
| Shared concurrency | Block transfers created one goroutine per index, and benchmark scheduling duplicated that machinery. A shared bounded worker implementation reuses goroutines, propagates the first error, cancels pending work, and joins active workers. Cancelled benchmark operations remain unfinished rather than counting as failures. | [Worker tests](../internal/parallel/parallel_test.go), [Benchmark tests](../internal/engine/benchmark_test.go), existing Azure transfer tests |

## Performance and implementation

The new [`internal/parallel`](../internal/parallel/parallel.go) helper is shared
by multipart uploads, ranged downloads, staged server-side copies, and the
benchmark. It uses standard-library synchronization and adds no dependency.
Directory creation and deferred permission restoration are centralized in
[`directories.go`](../internal/engine/directories.go). Destination checks also
avoid a second stat for ordinary, non-symlink destinations.

The scheduling microbenchmark processes 10,000 no-op indices with eight
workers. The same benchmark was run before and after the change, three times
for 300 ms per sample, on Linux/amd64 with Go 1.27.1 and an Intel Core Ultra 9
185H (`GOMAXPROCS=22`). Medians:

| Measurement | Before | After |
| --- | ---: | ---: |
| Scheduling time per operation | 4.749 ms | 0.177 ms |
| Allocated bytes per operation | 720,706 | 874 |
| Allocations per operation | 20,009 | 23 |

This is about a 27-fold reduction in scheduling time for the no-op workload,
especially relevant to skipped resume blocks. It is **not** a measured
27-fold improvement in file or network transfer throughput.

Reproduce the current measurement with:

```sh
go test ./internal/store/azure -run '^$' -bench '^BenchmarkInParallel$' -benchmem -benchtime=300ms -count=3
```

## Validation

All checks below passed in the Linux workspace. Network fixtures and the local
emulator required permission to use loopback sockets and Docker.

| Check | Result |
| --- | --- |
| `make check` | Formatting, vet, full tests, and race tests passed. |
| Final `go test -race -coverprofile=... ./...` | All 15 packages passed after the final code and regression-test changes. |
| Final `make lint` | Formatting and vet passed. |
| `make cross` | Linux, macOS, and Windows builds passed for amd64 and arm64. |
| `make e2e` with an isolated Azurite instance | All 60 checks passed; the temporary container was removed. |
| `go mod tidy -diff` | No module-file changes required. |
| `bash -n scripts/e2e.sh` | Passed. |
| `git diff --check` | Passed. |

Overall statement coverage increased from **71.1% to 73.6%**. Engine coverage
increased from 61.4% to 67.8%, and the new worker package reached 96.2%.
Coverage is evidence of exercised code, not proof that all behaviors are
correct; platform-specific files are covered only on the platform running
the tests.

The five new emulator checks exercise restored symlink timestamps,
asynchronous content-header overrides with checksum preservation,
attributes-only copies that retain data, and the data/record outcomes of
restarting an incomplete no-clobber download without resume.

The README and contributor instructions now describe these behaviors and
accurately distinguish cross-compilation from native platform tests.

## Validation limits and behavior changes

- Native macOS and Windows tests were not run in this Linux environment.
  Cross-compilation checks types and builds, not filesystem behavior.
  In particular, the macOS reflink fallback and Windows symlink timestamp
  implementation need native execution. Existing CI runs Windows tests;
  its regular matrix does not include macOS.
- Disabling macOS reflinks is an intentional correctness tradeoff. Automatic
  copies continue to work through the ordinary copy path, but lose cloning
  performance and space savings; `--reflink=always` now fails explicitly.
- No real Azure account, interactive OAuth flow, platform credential store,
  or live cloud throughput was exercised. Azurite and HTTP fixtures cover
  service interactions locally, including APIs the emulator does not fully
  implement, but cannot establish real-service parity.
- GNU `cp` comparisons used the available 9.7 binary. No claim is made that
  every GNU `cp` edge case or every combination of `azcp` options was tested.
- No tagged release was created as part of this audit.
